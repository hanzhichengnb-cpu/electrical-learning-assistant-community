# Reflect

Use after a real problem when reflection helps the user recognize a transferable method or error. A polished solution summary alone is not a lasting Insight.

1. Compare the actual problem, reasoning, retrieved knowledge and observed corrections with existing Problems and Insights. Never invent a user error.
2. If the result has clear value beyond this problem, propose one concise knowledge card **in the current conversation**: structure, trigger, conclusion, conditions, source pages, uncertainty and reason to save. Use [User-Facing Delivery](../references/user-delivery.md) for rendered formulas or evidence. Do not write a Candidate, Review, Knowledge Pack file or pending state just to make the proposal.
3. Ask at most once, with exactly **保存、修改后保存、暂不保存、不再建议**. If the user declines, end without a new artifact or review checkpoint.
4. Only after the user chooses 保存 or 修改后保存, prepare the requested Staging Candidate or concrete [Review](review.md). Follow [Canonicalize](canonicalize.md) only after separate approval of the exact content version shown to the user.

Canonical Insight means worth retaining, not independently mastered.
