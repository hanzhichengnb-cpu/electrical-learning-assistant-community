# Contributing

Contributions that improve reusable electrical-engineering study workflows are welcome.

## Keep personal workspaces private

Do not include any of the following in an issue, pull request, screenshot, commit, or example:

- course PDFs, lecture slides, or other source files;
- personal notes, annotations, study progress, or session logs;
- workspace state files, private knowledge objects, or source registries;
- absolute paths, account identifiers, API keys, or other credentials.

Use invented examples when a workflow needs sample content. Keep reusable Skill instructions separate from a learner's workspace and its data.

## Propose changes

Describe the learner task, the existing workflow, and the expected behavior. Keep changes focused. Update the public changelog when a change materially alters how the Skill behaves. Do not claim a workflow is supported unless its required workspace contract and tools are documented.

The public edition is maintained separately from the personal Skill source. Changes here do not automatically apply to a personal installation.
